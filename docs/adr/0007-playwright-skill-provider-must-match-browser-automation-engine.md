# The `playwright` skill only overrides the builtin when `browser_automation_engine.provider` equals its own name

`oh-my-openagent` was consistently choosing `openchamber_web` over `playwright-cli` for browser tasks, and launching headless when it did use `playwright-cli`. The plan was the documented one: create `~/.agents/skills/playwright/SKILL.md` to shadow the builtin `playwright` skill (per the plugin's own stated precedence, project > user > opencode > builtin), sharpening its "MUST USE" wording and defaulting every `open` to `--headed`.

That plan alone doesn't work. Reading `oh-my-openagent`'s bundled source (`~/.cache/opencode/packages/node_modules/oh-my-openagent/dist/index.js`) shows a provider-gating filter ahead of the usual scope-priority merge: any *discovered* skill named `playwright` or `agent-browser` is kept only if its name equals `pluginConfig.browser_automation_engine.provider`; otherwise it's dropped before scope priority is even considered, and the matching builtin (also named `playwright`) fills the slot instead. This repo's `opencode/oh-my-openagent.json` had `browser_automation_engine.provider` set to `"playwright-cli"` — a value that exists to pick *which builtin body* gets synthesized under the `playwright` name (there's a `playwright-cli`-flavored builtin and an MCP-flavored one, both named `"playwright"` internally), not to name a real skill. A discovered skill literally named `playwright` fails the gate against that value and is silently discarded, every time, regardless of scope priority.

Decided on: keep the user-scope `~/.agents/skills/playwright/SKILL.md` as the override, and set `browser_automation_engine.provider` back to `"playwright"` (the schema default) in `opencode/oh-my-openagent.json` so the gate's equality check passes. The skill's own body handles `playwright-cli` invocation directly (it doesn't need the config to name that provider) — the config's only remaining job here is naming-match to survive the filter.

Consequence: if `~/.agents/skills/playwright/SKILL.md` ever needs replacing or renaming, check this gate first — a skill named anything other than `playwright` or `agent-browser` skips the filter entirely (and coexists with the builtin instead of replacing it), while `playwright` or `agent-browser` must have their provider value matched exactly or they're dropped outright. This is enforced in the plugin's own bundled code, not documented in its README or JSON schema descriptions, and can silently regress if the provider value is ever changed back for an unrelated reason.
