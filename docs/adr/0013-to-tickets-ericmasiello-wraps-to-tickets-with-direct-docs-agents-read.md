# to-tickets-ericmasiello wraps to-tickets with a direct docs/agents read

`to-tickets` (synced from `mattpocock/skills`) only ever says the issue tracker and triage label vocabulary "should have been provided to you... run `/setup-matt-pocock-skills`" — it never reads `docs/agents/issue-tracker.md`/`triage-labels.md` itself. It relies entirely on the `## Agent skills` block `setup-matt-pocock-skills` writes into `AGENTS.md`/`CLAUDE.md` to have told the agent those files exist. `setup-ericmasiello-skills`'s sidecar mode (ADR 0006) deliberately skips writing that block for restricted repos, since no consuming skill reads the block itself — it exists only for a human skimming the repo root. That assumption broke in practice. In the `studio` monorepo, the sidecar's `docs/agents/issue-tracker.md` resolves fine as a symlink and holds real tracker config (Jira, project ERICRULEZ), but `/to-tickets` still fell back to asking where to put tickets. Nothing in context told it the file was there to read.

The same gap exists identically in `triage`, `to-spec`, `wayfinder`, and `code-review` — all synced from `mattpocock/skills`, all carrying the same "should have been provided to you" phrasing instead of a direct read.

Decided on: a new self-authored, user-invoked wrapper per upstream skill (starting with `to-tickets-ericmasiello`), following the same decorator relationship `setup-ericmasiello-skills` has with `setup-matt-pocock-skills`. It never edits the upstream skill, since `npx skills update` would silently discard the edit, and defers to its process unmodified. Its one addition is a step, before deferring, that reads `docs/agents/issue-tracker.md` and `triage-labels.md` directly from the filesystem whenever they exist, regardless of whether `AGENTS.md`/`CLAUDE.md` mentions them. That step is factored into a shared, non-skill reference file, `.agents/skills/_ericmasiello-shared/LOAD-DOCS-AGENTS.md` — mirroring the existing `_studio-shared/LABELS.md` convention — so `triage-ericmasiello`, `to-spec-ericmasiello`, `wayfinder-ericmasiello`, `code-review-ericmasiello`, and a domain-docs-reading `domain-modeling-ericmasiello` can point at the same step later instead of each repeating it. Checking the sidecar's `project.json` `restricted` flag first was rejected as an unnecessary lookup: a direct read behaves identically whether or not sidecar mode was ever used, and costs nothing extra when the files simply don't exist.

Consequence: `/to-tickets-ericmasiello` is the one to run instead of `/to-tickets` going forward on any repo that might be in sidecar mode. Building wrappers for the other four affected skills is deferred until the same gap is actually hit for each, rather than built speculatively now.
