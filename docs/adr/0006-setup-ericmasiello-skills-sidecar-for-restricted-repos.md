# setup-ericmasiello-skills wraps setup-matt-pocock-skills with a sidecar for restricted repos

`setup-matt-pocock-skills` (synced from `mattpocock/skills`) assumes it can edit `AGENTS.md`/`CLAUDE.md` and create `docs/agents/`, `CONTEXT.md`, `docs/adr/` inside whatever repo it's run in. That broke on a CODEOWNERS-gated monorepo (`~/Sites/studio`) shared with coworkers who don't use these skills: `AGENTS.md` there is locked to a single team in `CODEOWNERS` and opens with "do not edit this file unless explicitly instructed," and the user didn't want personal-tooling files landing in a shared tree at all, tracked or not.

Investigated three shapes before landing here. Editing `docs/agents/issue-tracker.md`'s readers (`code-review`, `domain-modeling`, `to-spec`, `to-tickets`, `triage`, `wayfinder`) to check an external location first was rejected: all six are also synced from `mattpocock/skills`, so hand-editing any of them risks `npx skills update` silently discarding the change, multiplied across six files instead of one. Editing `setup-matt-pocock-skills` itself the same way, for the same reason. A fully external, untracked-anywhere sidecar (e.g. keyed by path hash under `~/.local/share/`, mirroring how Claude Code and opencode itself already store per-project state outside the project) was rejected because the user wants this config checked in and manageable, not opaque personal state with no history.

Decided on: a sidecar tracked inside this repo, at `.agents/_config/projects/<key>/`, automatically reachable at `~/.agents/_config/projects/<key>/` for free (that path is already a symlink into this repo, per ADR-0002). `<key>` is the normalized `git remote get-url origin` (or a path slug when there's no remote) — human-readable and stable across re-clones, not an opaque hash. A new, self-authored `setup-ericmasiello-skills` skill asks one extra question up front (is this repo restricted?), and when yes, creates local-only symlinks (`docs/agents`, `docs/adr`, `CONTEXT.md`) pointing at the sidecar and registers them in the target repo's `.git/info/exclude` — never its tracked `.gitignore`. It then defers to `setup-matt-pocock-skills`'s own Explore/Present/Confirm/Write process verbatim, skipping only its one instruction to edit the root `AGENTS.md`/`CLAUDE.md` file (confirmed decorative: no consuming skill reads that block, only `setup-matt-pocock-skills` writes it). Because the symlinks make the usual relative paths resolve into the sidecar transparently, all six downstream skills work completely unmodified.

Consequence: a restricted repo gets one local-only symlink per redirected path plus three lines in `.git/info/exclude` — nothing tracked, committed, or visible to `git status`, teammates, or CODEOWNERS review, but not literally zero bytes on disk either. `setup-ericmasiello-skills` is the only skill anyone should invoke going forward instead of `setup-matt-pocock-skills` directly, since it defers to the latter's unmodified logic either way and is the only place that knows whether a given repo is in sidecar mode.
